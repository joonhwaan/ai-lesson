AI 기초
도구 호출
이제 컨텍스트의 동작 원리를 이해했으니, AI 모델이 단순히 텍스트를 생성하는 것을 넘어 무엇을 할 수 있는지 살펴보겠습니다. AI 모델은 도구 호출을 통해 동적으로 작업을 수행하고 정보를 가져올 수 있습니다.

AI 모델을 API 엔드포인트에 비유했던 것을 기억하시나요? 도구 호출은 그 모델이 스스로 다른 API를 호출할 수 있도록 하는 것입니다. 마치 AI 모델이 새로운 능력을 익힌 것과 같습니다.

비유를 들어 볼게요. 전화로 친구의 저녁 요리를 도와준다고 상상해 보세요. 알고 있는 정보로 지시를 줄 수는 있지만, 그들의 냉장고에 무엇이 있는지 보거나 만들고 있는 음식을 맛볼 수는 없습니다.

이제 친구가 냉장고 안 사진을 보내거나 오븐의 정확한 온도를 알려 준다고 해봅시다. 실시간 정보에 접근할 수 있으니 훨씬 더 나은 조언을 할 수 있겠죠. 본질적으로 이것이 AI 모델에서의 도구 호출이 하는 일입니다.

도구 호출이 작동하는 방식
개발자가 AI 애플리케이션을 만들 때 AI 모델이 사용할 수 있는 특정 “도구”를 정의할 수 있습니다. 이 도구들은 모델이 단순히 추론하고 텍스트로 답하는 것을 넘어 기능을 확장해 주는 특수 능력과 같습니다.

이미 모르는 사이에 도구 호출을 써 본 적이 있을 거예요! ChatGPT에 이미지 생성, 웹 검색, 코드 실행을 요청하면, 사실 백그라운드에서 도구가 사용됩니다.

내부적으로는 다음과 같이 동작합니다:

AI 모델이 요청을 받고 추가 기능이 필요하다고 판단합니다
어떤 도구를 사용할지와 전달할 매개변수를 지정하는 JSON(구조화된 데이터 형식) 형식의 특수 응답을 구성합니다
애플리케이션이 해당 도구를 실행하고 결과를 반환합니다
AI 모델이 그 결과를 컨텍스트에 반영하고 대화를 이어갑니다
코딩에서 도구가 중요한 이유
소프트웨어를 만들 때 도구는 AI 모델이 다음을 할 수 있게 해 주기 때문에 매우 강력합니다:

코드베이스의 파일을 읽고 쓰기
관련 함수나 패턴을 찾기 위해 코드를 검색하기
코드를 테스트하거나 패키지를 설치하기 위해 셸 명령 실행하기
최신 정보를 얻기 위해 문서에 접근하거나 웹 검색하기
린터나 테스트를 실행해 오류 확인하기
도구가 없으면 AI 모델은 컨텍스트에서 사용자가 명시적으로 제공한 정보로만 제한됩니다. 도구가 있으면 코드베이스를 능동적으로 탐색하고 상호작용할 수 있습니다.

도구 호출에는 무엇이 들어 있나요?
모든 도구에는 세 가지 핵심 구성 요소가 있습니다:

이름(read_file 또는 search_web 같은)
설명 — 모델에 도구를 언제 그리고 어떻게 사용해야 하는지 알려줍니다
매개변수 — 도구가 작동하는 데 필요한 입력값입니다
다음은 도구 정의가 어떤 모습일 수 있는지에 대한 예시입니다:


{
  "name": "read_file",
  "description": "Read the contents of a file from the codebase",
  "parameters": {
    "filepath": "The path to the file to read"
  }
}
AI 모델이 이 도구를 사용하고자 할 때는 다음과 같은 응답을 생성합니다:


{
  "tool": "read_file",
  "parameters": {
    "filepath": "src/components/Button.tsx"
  }
}
그러면 애플리케이션이 해당 파일을 읽고 그 내용을 대화 컨텍스트에 추가하여, 모델이 Button 컴포넌트를 이해하고 관련된 변경 사항을 제안할 수 있게 합니다.

도구 비용
토큰과 요금에 대해 이야기했던 거 기억하나요? 도구 호출은 두 가지 방식으로 토큰을 소모합니다:

도구 정의가 입력 컨텍스트에 포함됩니다(보통 도구당 수백 토큰)
도구 결과가 출력 컨텍스트에 추가됩니다(도구가 반환하는 내용에 따라 달라짐)
즉, 도구 사용이 많은 대화는 컨텍스트 윈도우가 더 빨리 차고 비용도 더 듭니다. 다만 실시간 정보에 접근하면 AI의 효용이 크게 높아지므로, 보통 그 트레이드오프의 가치는 충분합니다.

도구 호출이 일어나면 AI 모델은 도구 호출 시점까지의 컨텍스트를 다시 평가합니다. Cursor와 같은 도구에서는 컨텍스트를 모델에 재전송하기 때문에 캐시된 입력 토큰 사용량이 더 많이 표시됩니다.

기본 제공 도구를 넘어
최근 MCP(Model Context Protocol)라는 새로운 표준이 만들어졌습니다. AI 모델이 다양한 애플리케이션에서 도구를 사용하고 통합할 수 있게 해주는 범용 방식이라고 보면 됩니다.

USB가 컴퓨터와 기기를 연결하는 표준이 되었듯, MCP는 도구를 AI 모델에 연결하는 표준을 지향합니다. 즉, 개발자가 한 번 도구를 만들면 여러 AI 앱에서 그대로 쓸 수 있다는 뜻입니다.

예를 들어, 디자인 파일을 위해 Figma에 연결하고, 이슈 열람 및 관리를 위해 Linear에 연결하거나, 데이터베이스에 연결해 데이터를 직접 쿼리할 수도 있습니다. 또한 내부 도구와 API와의 통합을 위해 자체 MCP 서버를 만들 수도 있습니다.

이제 도구 호출을 이해했으니, AI 모델이 여러 도구를 순차적으로 사용할 때 무엇이 일어나는지 살펴보겠습니다. 바로 그 지점에서 에이전트가 더 흥미로워집니다.
