환각
이제 AI 모델의 동작 방식을 이해했으니, 많은 개발자들이 AI 도구를 처음 사용할 때 겪는 문제인 환각에 대해 이야기해 보겠습니다.

환각은 AI 모델이 겉보기에는 그럴듯하지만 실제로는 틀린 정보를 자신 있게 만들어 내는 현상을 말합니다. 마치 잘 알지 못하는 주제에 대해 블러핑으로 대화를 이어가는 것과 비슷합니다.

왜 모델은 환각을 일으킬까요?
AI 모델이 학습한 패턴을 바탕으로 다음 토큰을 예측한다고 했던 것을 기억하시나요? 때로는 그 패턴이 모델을 잘못된 방향으로 이끕니다.

이런 모델을 매우 강력한 텍스트 자동완성처럼 생각해 보세요. "The weather today is..."라고 입력하면 휴대폰이 흔한 패턴에 따라 "sunny"나 "cloudy"를 제안하듯이, AI 모델도 비슷하게 작동하지만 전체 개념과 코드 블록 수준에서 이를 수행합니다.

AI 모델이 모르는 내용을 만났을 때 항상 "I don't know."라고 하지는 않습니다. 대신, 지금까지 본 패턴을 바탕으로 가장 그럴듯한 답을 생성합니다. 코딩에서는 다음과 같을 수 있습니다:

실제로 존재하지 않는 그럴듯한 API 메서드 만들어내기
서로 다른 프로그래밍 라이브러리나 프레임워크 간 문법을 뒤섞기
그럴듯해 보이지만 실제로는 없는 설정 옵션 만들기
모델 제공자는 인터넷의 방대한 텍스트(및 기타 독점 데이터)를 사용해 특정 시점까지 모델을 학습시키는데, 이 날짜를 “지식 컷오프(knowledge cutoff)”라고 합니다. 이 시점이 모델이 가진 최신 지식입니다. 이 날짜 이후에 만들어진 라이브러리에 대해 묻는다면 AI 모델이 잘못된 해법을 제안할 수 있습니다.

실제 사례로 보는 환각
개발자가 겪는 환각의 실제 예시를 몇 가지 보여드리겠습니다.

첫 번째는 겉보기에는 맞아 보이지만 실제로는 존재하지 않는 패키지에서의 import입니다.


// AI 제안:
import { debounce } from "react";
// 실제: debounce는 React에서 내보내지지 않습니다!
// lodash를 사용하거나 직접 작성해야 합니다
두 번째는 그럴듯해 보이지만 실제로는 가짜인 클래스의 메서드입니다:


# AI 제안:
df.remove_outliers(threshold=3)
# 실제: pandas DataFrame에는 이 메서드가 없음
# 이상치 제거를 직접 구현해야 함
마지막으로, 거의 올바른 구성 파일:


// AI가 package.json에 대해 제안:
{
  "type": "module",
  "exports": "./index.js",
  "browser": true // <- 이것은 유효하지 않습니다!
}
AI 모델을 더 많이 다루다 보면 환각을 알아차리는 요령이 생깁니다.

모델이 반환한 결과를 의심하고, 제안은 따로 검증하는 것이 좋습니다. 이를 더 쉽게 하려면 에디터나 애플리케이션 환경을 설정해 피드백을 받도록 하세요.

예를 들어 Cursor에서는 잘못된 import 구문이 있을 경우 해당 import가 존재하지 않는다는 오류가 표시되며, 이 오류를 AI 모델에 피드백으로 다시 전달할 수 있습니다.

기타 모델의 한계
모델이 확신에 차서 틀린 답을 내놓기도 합니다.

실제로는 틀렸는데도 “정말 맞습니다!”라는 응답을 받을 수 있습니다. 또 일부 모델은 진짜 무작위 수 생성이나 단어에서 특정 문자의 등장 횟수를 세는 등 결정적 소프트웨어가 잘하는 작업에서 어려움을 겪습니다.

그럼에도 불구하고, 환각과 한계가 있어도 AI 모델은 여전히 매우 유용합니다.

AI와 효과적으로 협업하려면 검증 중심의 사고방식이 중요합니다. 모든 제안은 출발점일 뿐, 최종 답이 아닙니다. 겉보기엔 일이 늘어난 듯하지만, 코드를 그대로 베끼지 않고 동작을 이해하도록 하여 더 나은 개발자로 성장하게 합니다.

이 과정 전반에 걸쳐, 생성된 코드의 품질을 높이고 AI 모델과 제대로 작업하는 방법을 제안하겠습니다.

모델과 상호작용하는 방법을 논의하기 전에, 모델이 어떻게 “생각”하고 어떻게 과금되는지 더 이해할 필요가 있습니다. 다음 강의에서 자세히 살펴보겠습니다.
