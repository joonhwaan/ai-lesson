코딩 에이전트
에이전트 활용하기
개발자들은 이제 에이전트로 아주 많은 코드를 작성합니다. 모든 줄을 직접 타이핑하는 대신 에이전트와 대화하고, 에이전트가 대신 코드를 작성하게 합니다.

Foundations 과정에서는 에이전트의 핵심 동작 방식, 즉 강력한 도구를 제공하고 루프에서 자율적으로 실행되도록 하는 방법을 배웠습니다. 이 과정에서는 소프트웨어를 개발할 때 코딩 에이전트를 효과적으로 활용하는 전략을 살펴봅니다.

에이전트 하니스란?
Cursor는 코딩 에이전트가 내장된 AI 에디터입니다. 이 에이전트는 "하니스"라고 불리는 환경 안에서 실행되며, 이 환경은 세 가지로 이루어져 있습니다:

Instructions: 동작을 안내하는 시스템 프롬프트와 규칙 같은 지시
Tools: 파일 편집, 코드베이스 검색, 터미널 실행 등 다양한 도구
Model: 작업에 선택한 에이전트 모델
코딩 에이전트는 사용자가 부여한 목표에 따라 작업을 수행하도록 도와줍니다. 각 하니스는 어떻게 튜닝되었는지와 어떤 모델을 사용하는지에 따라 동작이 조금씩 다릅니다.

어떤 모델은 셸 명령어를 더 자주 호출하도록 학습되어 있습니다. 다른 모델은 더 명시적인 지시를 필요로 합니다. Cursor에서는 가능한 모든 프런티어 모델을 지원하고, 그들이 접근할 수 있는 도구를 포함해 하니스를 최대한 최적화하는 것을 목표로 하고 있습니다.

두 번째 프롬프트가 훨씬 더 좋습니다. 코드베이스에 기반한 구체적인 지시사항(기존 파일, 컴포넌트, 명확한 범위)을 제공하기 때문입니다. 에이전트는 새로운 패턴을 만들어내는 대신 여러분이 사용하는 패턴을 따릅니다.

새로운 기능을 만드는 방법과 여러 파일에 걸친 대규모 변경을 계획하는 방법을 배울 때 이 내용을 더 자세히 다루겠습니다.

어떤 방식이 에이전트가 가장 좋은 결과를 내도록 도와주나요?


원하는 내용을 대략적으로만 설명하고, 세부 사항은 에이전트가 알아서 파악하게 둔다.

구체적인 파일, 기존 패턴을 참고하고, 명확한 범위와 경계를 정의한다.

컨텍스트 관리하기
에이전트와 작업할 때 대화를 이어 가면서 메시지, 도구 호출, 파일 내용 등의 컨텍스트가 쌓입니다. 이 컨텍스트는 에이전트의 작업 메모리이며, 한계가 있습니다.

에이전트가 얼마나 많은 컨텍스트를 사용하고 있는지 염두에 두세요. 새로운 작업으로 전환할 때나 에이전트가 실수를 하기 시작한다고 느껴지면 새 대화를 시작하세요.

아직 같은 기능을 계속 작업 중이고 에이전트가 이전 메시지에서 유용한 컨텍스트를 가지고 있다면 대화를 이어 가는 것이 좋습니다. 하지만 에이전트가 계속 제자리걸음만 한다면 기능 작업 도중이더라도 새로 시작하세요. 이전 대화를 참조하면 에이전트가 채팅 기록을 읽을 수 있습니다.

최신 모델은 사용자를 대신해 컨텍스트를 찾는 데 매우 능숙해지고 있습니다. 시맨틱 검색 같은 도구가 주어지면 에이전트는 필요에 따라 관련 파일을 가져올 수 있습니다. 정확한 파일을 알고 있다면 태그하세요. 그렇지 않다면 일반적인 설명을 주고 에이전트가 올바른 파일을 찾게 하세요.

흔한 실패 패턴: 스코프 크리프
가장 흔한 실수 중 하나는 충분한 계획 없이 너무 큰 변경을 한 번에 요청하는 것입니다. 그러면 에이전트가 관련 없는 부분을 수정하거나, 원치 않는 파일을 건드리거나, 작업의 초점을 잃을 수 있습니다.

이런 조짐이 보이면 잠시 멈추고, 작업을 더 작은 단위로 나눌 수 있는지 생각해 보세요. 야심찬 기능을 계획 중이라면, 기능 만들기에서 탄탄한 계획과 스펙을 설계하는 방법을 다룹니다. 그런 계획을 세우고 첫 대화를 시작한 뒤에는, 더 작은 후속 대화로 나누어 반복 작업을 하는 편이 더 빠른 경우가 많습니다.
