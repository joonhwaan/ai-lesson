# 세션 2 해설 스크립트 — 자주 쓰는 명령 & 슬래시 커맨드

> 🎙️ 이 문서는 강사가 그대로 읽거나 참고해 설명할 수 있는 해설 대본입니다. 본문: [세션 2 강의 자료](session-02.html)
>
> (기준 시점 2026-06 · 명령 이름·동작은 버전마다 바뀌니 원리 중심으로 전달하고, 최신 목록은 `/help`로 확인하라고 안내)

## [프레이밍 · 8분] 명령은 워크플로의 단축키

🎙️ 두 번째 시간이에요. 지난 시간에 탐색→계획→실행→검증 루프를 배웠죠? 오늘은 그 루프를 *빠르게 굴리는 손동작*, 그러니까 명령을 익힐 거예요.

생각해 보세요. 같은 일을 말로 길게 풀어서 부탁할 수도 있어요. "지금까지 바꾼 거 리뷰해주고 테스트도 돌려서 통과하면 알려줘." 매번 이렇게 타이핑하면 느리고, 빠뜨리기도 해요. 자주 하는 동작은 한 단어 명령이 빠르고 정확해요. 사람으로 치면, 매번 "복사하고 붙여넣어 주세요"라고 말하는 대신 Ctrl+C, Ctrl+V를 쓰는 거랑 같아요.

🎙️ 명령은 크게 두 종류예요. 하나는 **내장 슬래시 명령**, `/clear`나 `/review`처럼 도구가 기본으로 주는 거. 또 하나는 **커스텀 슬래시 커맨드**, 내가 직접 만든 재사용 워크플로예요. 여기에 `!`나 `@` 같은 입력 보조가 더해지죠. 오늘 이 셋을 다 다룹니다.

## [핵심① · 24분] 자주 쓰는 내장 명령 지도

🎙️ 먼저 내장 명령이에요. 그런데 시작 전에 꼭 강조할 게 있어요 — **전부 외우지 마세요.** 용도별로 "이런 게 있다"만 알아두고, 정확한 이름은 `/help`로 찾으면 돼요. 외우는 게 아니라 발견하는 습관이 핵심이에요.

화면 표를 용도별로 같이 볼게요. 첫째 컨텍스트 관리 — `/clear`, `/compact`, `/memory`. 작업 전환할 때 리셋하고, 길어지면 압축하고, 프로젝트 규칙인 CLAUDE.md를 편집하는 거예요. 둘째 코드 작업 — `/init`으로 새 레포에 CLAUDE.md를 만들고, `/review`로 변경분을 리뷰해요. 셋째 설정과 진단 — `/config`, `/model`, `/permissions`, `/cost`, `/doctor`. 환경설정, 모델 전환, 권한, 비용 확인, 설치 점검이에요. 넷째 확장 — `/agents`, `/mcp`, `/hooks`. 서브에이전트랑 MCP 서버랑 훅인데, 이건 세션 4랑 5에서 깊게 다뤄요. 다섯째 세션 — `/resume`으로 이전 대화 재개, `/export`로 내보내기, 그리고 `/help`요.

🎙️ 이 중에 제일 자주 쓰게 될 두 개를 다시 짚을게요. 지난 시간에 배운 `/clear`랑 `/compact`예요. **작업이 바뀌면 `/clear`로 잔상을 지우고, 같은 작업이 길어지면 `/compact`로 압축**해요. 이 두 개는 거의 매일 쓰게 될 거예요.

💬 예상 질문: "명령이 가물가물한데 대충 찍어서 쳐도 되나요?" → 안 돼요. 모르는 명령을 추측하지 마세요. `/help`가 진실의 원천이에요. 버전마다 명령이 생기고 사라지거든요. 이 표도 2026년 6월 기준이라, 여러분이 볼 땐 다를 수 있어요. 그래서 더더욱 `/help`예요.

## [핵심② · 20분] 입력 affordance — !, @, 이미지, #

🎙️ 슬래시 명령 말고도, 입력창에서 바로 쓰는 보조 기호들이 있어요. 이게 작업을 확 줄여줘요. 화면 표를 보세요.

첫째 느낌표 `!`. 인라인으로 셸을 실행하고 그 결과가 대화에 들어와요. `!npm test`, `!git status` 이렇게요. 둘째 골뱅이 `@`. 파일이나 디렉터리를 참조하는데 경로 자동완성이 돼요. `@src/routes/products.js 를 봐줘` 식이죠. 셋째 이미지. 그냥 붙여넣거나 드래그하면 첨부돼요. 에러 스크린샷이나 디자인 시안을 줄 때 좋아요. 넷째 샵 `#`. 메모리에 추가하는 건데, CLAUDE.md에 규칙을 기록해요. "항상 인라인 스타일 대신 CSS 모듈 써" 같은 걸 박아두는 거죠.

🎙️ 여기서 `!`를 좀 더 설명할게요. 에이전트한테 "테스트 돌려봐"라고 시키는 거랑, 내가 직접 `!npm test`를 치는 건 달라요. 후자는 **내가 직접 실행해서 결과를 곧장 컨텍스트에 넣는** 거예요. 특히 인터랙티브 로그인, 예를 들어 `gcloud auth login` 같은 건 에이전트가 못 하잖아요. 그런 건 내가 `!`로 실행하고 출력만 공유하면 돼요. 비유하면, 통역사한테 "저 문 열어줘"라고 부탁하는 대신 내가 직접 열고 "열렸어" 하고 알려주는 거예요.

## [핵심③ · 22분] 커스텀 슬래시 커맨드 만들기

🎙️ 이제 오늘의 하이라이트예요. 같은 지시를 매번 길게 타이핑하고 있다면, 그걸 커맨드로 굳혀버리세요. 마크다운 파일 하나면 끝이에요.

화면처럼 위치는 두 군데예요. `.claude/commands/이름.md`는 프로젝트용이라 팀과 공유되고 git에 커밋돼요. `~/.claude/commands/이름.md`는 개인용이라 내 모든 프로젝트에서 쓰여요. 호출은 `/이름 인자` 이렇게 하고요.

🎙️ 화면의 `pr-check.md` 예시를 보세요. 위에 frontmatter로 description이랑 argument-hint를 적고, 본문에 할 일을 적어요. 변경분을 리뷰하는데 `!git diff --stat`으로 범위 보고, 버그랑 빈 catch 같은 silent fail 점검하고, `!npm test`로 통과 확인하라고요. 그리고 맨 아래 `$ARGUMENTS`가 호출할 때 넘긴 인자 전체예요. `$1`, `$2`로 위치 인자도 쓸 수 있고요.

🎙️ 핵심 포인트 두 개. 하나, 본문에 `!`랑 `@`를 그대로 박아둘 수 있어요. 그러면 명령 한 번에 셸 실행이랑 파일 컨텍스트가 같이 딸려와요. 둘, 좋은 커맨드의 기준이에요 — **세 번 이상 반복했고, 단계가 고정된** 작업이 후보예요. 매번 달라지는 일을 억지로 커맨드로 만들면 오히려 방해가 돼요. 이 경계는 다음 세션 "스킬"에서 더 정교하게 가를 거예요. 규칙, 스킬, 커맨드 셋의 차이로요.

💬 예상 질문: "그럼 모든 걸 다 커맨드로 만들면 좋은 거 아니에요?" → 아니에요. 고정된 반복만 커맨드로요. 한 번 쓰고 말 거나 매번 내용이 달라지는 건 그냥 말로 시키는 게 나아요. 커맨드가 너무 많아지면 그것대로 관리 부담이에요.

## [핵심④ · 10분] 자주 쓰는 명령 레시피

🎙️ 명령이랑 보조 기호를 엮으면 지난 시간 루프가 손에 착 붙어요. 화면 레시피 세 개를 볼게요.

레시피 A, 변경분 마무리. `!git diff`로 바꾼 거 확인하고, `/review`로 리뷰받고, 수정 반영하고, `!npm test`로 검증하고, 커밋 요청. 레시피 B, 새 레포 진입. `/init`으로 CLAUDE.md 만들어 관례 파악하고, `@핵심파일`로 탐색하고, 플랜 모드로 작업 시작. 지난 시간 탐색 단계가 여기 그대로 들어가죠. 레시피 C, 작업 전환. `/clear`하고 새 작업 프롬프트를 경로·기대출력·참조 명시해서 던지기. 지난 시간 §5 프롬프트 패턴이 그대로예요.

🎙️ 마무리 실습이에요. 오늘 배운 것 중에 실제로 쓸 다섯 개만 골라서 적어두세요. 자주 쓰는 다섯 개 더하기 `/help`로 나머지 발견 — 이게 가장 빠른 숙달 경로예요. 다 외우려고 하지 마세요.

한 문장으로 정리할게요 — **명령은 워크플로의 단축키예요.** 내장 명령은 용도별로 알아두고 `/help`로 발견하고, `!`랑 `@`로 셸이랑 파일을 끌어오고, 반복 작업은 커스텀 커맨드로 굳혀서 지난 시간 루프를 빠르게 굴린다. 다음 시간엔 한 단계 위, 특정 상황에서 자동으로 발동되는 스킬을 만들어 볼게요. 수고하셨습니다. 질문 받을게요.
