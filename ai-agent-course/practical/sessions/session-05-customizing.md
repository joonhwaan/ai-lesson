## 1. 커스터마이징 3층 개요

세션 2에서 "규칙 vs 스킬 vs 커맨드"의 경계를 살짝 봤다. 이번엔 그 ==자동화 축==을 제대로 세운다. 커스터마이징은 크게 세 층이다.

| 층 | 무엇 | 언제 발동 | 어디에 |
|------|------|-----------|--------|
| **규칙(`CLAUDE.md`)** | 코딩 스타일·관례·금지사항 | ==항상== — 매 대화에 자동 주입 | `~/.claude/CLAUDE.md`(전역) · 프로젝트 `CLAUDE.md` |
| **훅(hooks)** | 명령 자동 실행(테스트·알림 등) | ==특정 이벤트==(도구 실행 전후, 응답 완료 등) | `settings.json` |
| **MCP 서버** | 외부 도구·데이터 연결(브라우저·DB 등) | ==필요할 때== 에이전트가 호출 | MCP 설정 + `/mcp` 관리 |

> [!NOTE] 한 축으로 정리하면
> ==규칙은 "무엇을 알아야 하나"(맥락), 훅은 "무엇이 자동으로 일어나야 하나"(동작), MCP는 "무엇과 연결되나"(도구)==. 셋은 역할이 겹치지 않는다. 일을 어디에 둘지 헷갈리면 이 한 줄로 가른다.

> [!TIP] 규칙과 훅을 혼동하지 말 것
> "커밋 전에 항상 테스트해"를 `CLAUDE.md`에 적으면 =='그러길 바라는' 지시==일 뿐 — 에이전트가 잊을 수 있다. **반드시 매번 실행돼야 하는 동작은 훅**이다(§3). 규칙은 권유, 훅은 강제다.

## 2. `CLAUDE.md` 규칙 — 항상 주입되는 관례

입문 레슨 12에서 다룬 에이전트 맞춤 설정의 핵심이 `CLAUDE.md`다. 프로젝트 루트(또는 전역 `~/.claude/`)에 두면 ==매 대화 시작 시 자동으로 컨텍스트에 주입==된다. 매번 "우린 인라인 스타일 대신 CSS 모듈 써"를 반복할 필요가 없어진다.

```markdown
<!-- 프로젝트 루트 CLAUDE.md (예시) -->
# 프로젝트 규칙

## 코딩 스타일
- 에러 처리는 Toast로 통일 (alert 금지)
- API 응답은 `{ data, total }` 형태로 반환

## 금지사항
- 빈 catch 블록 금지 — 최소 console.error
- `*/site/` 아래 생성 HTML 직접 수정 금지

## 빌드
- .md 수정 후 반드시 `build.py` 실행 후 커밋
```

| 위치 | 범위 | 쓰임 |
|------|------|------|
| `~/.claude/CLAUDE.md` | ==전역== — 모든 프로젝트 | 내 개인 습관·공통 규칙 |
| 프로젝트 `CLAUDE.md` | ==이 레포== — 팀 공유(git 커밋) | 이 프로젝트의 관례·아키텍처 |

> [!IMPORTANT] ==장황하게 말고 핵심 규칙만==
> `CLAUDE.md`는 매 대화에 통째로 주입된다. 길수록 ==컨텍스트를 먹고 핵심이 묻힌다==. 소설처럼 쓰지 말고, 자주 어기는 관례·금지사항·빌드 절차만 불릿으로. 세션 2의 `#`(메모리 추가)로 한 줄씩 쌓아가는 것도 좋은 습관이다.

> [!NOTE] 규칙은 "권유"라는 한계
> 주입됐다고 100% 지켜지는 건 아니다. 중요하고 ==매번 강제돼야 하는 것==(테스트·포맷)은 훅으로 넘긴다(§3). 규칙은 맥락 제공, 훅은 실행 보장 — 역할을 나눠라.

## 3. 훅(hooks) — 이벤트에 자동 실행

훅은 ==특정 이벤트가 일어날 때 내가 정한 명령을 자동 실행==하는 장치다. `settings.json`에 설정한다. 대표적인 쓰임:

- **도구 실행 전후** — 예: 파일 편집 후 자동 포맷터(`prettier`) 실행, 위험한 명령 차단
- **응답 완료 시** — 예: 알림음·데스크톱 토스트로 "끝났다" 알리기
- **커밋·작업 마무리 시점** — 예: 테스트·린트 자동 실행

```json
// settings.json (대표 예시 · 필드/이벤트명은 버전마다 다를 수 있음)
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "prettier --write \"$FILE\"" }
        ]
      }
    ]
  }
}
```

> [!IMPORTANT] 훅의 존재 이유 — "강제 실행"
> ==항상 자동으로 일어나야 하는 동작은 메모리·규칙이 아니라 훅으로 해야 실제로 실행된다.== `CLAUDE.md`에 "편집하면 포맷해"라고 적어도 에이전트가 건너뛸 수 있지만, 훅은 ==이벤트가 나면 무조건== 돈다. "권유"와 "강제"의 차이다.

> [!TIP] 정확한 이벤트 이름은 `/hooks`로 확인
> 이벤트 이름(`PostToolUse` 등)·매처 문법은 버전마다 다를 수 있다. ==지어내지 말고== `/hooks`나 설정 UI에서 현재 지원되는 이벤트 목록을 보고 고른다. 세션 2의 "추측하지 말고 `/help`"와 같은 원칙이다.

> [!WARNING] 훅은 무조건 돈다 = 양날의 검
> 훅 명령이 느리거나 실패하면 ==매 이벤트마다== 발목을 잡는다. 무거운 작업(전체 빌드 등)을 빈번한 이벤트에 걸지 말고, 빠르고 실패해도 안전한 명령만. 알림처럼 가벼운 것부터 시작하길 권한다.

## 4. MCP 서버 연결 — 외부 도구·데이터 붙이기

입문 레슨 05에서 MCP를 ="도구계의 USB"=라고 배웠다. **MCP(Model Context Protocol)**는 에이전트와 외부 도구·데이터 소스를 ==표준 프로토콜==로 잇는다. 한 번 붙여두면 에이전트가 필요할 때 그 도구를 호출한다.

| 무엇을 붙이나 | 예 |
|---------------|-----|
| 브라우저 자동화 | 실제 페이지 열어 클릭·스크린샷 |
| 데이터베이스 | 스키마 조회·쿼리 실행 |
| 이슈 트래커·협업 도구 | 이슈 읽기·코멘트·PR 연동 |
| 외부 API·문서 | 사내 위키·검색 등 |

```bash
# MCP 서버 관리
/mcp            # 연결된 서버 목록·상태 확인, 인증 등

# 설정은 settings.json(또는 전용 mcp 설정)에 서버를 등록
# (서버마다 실행 방식·인증이 다르니 각 서버 문서를 따른다)
```

> [!NOTE] 표준 프로토콜이라는 게 핵심
> USB처럼, ==한 번 규격을 맞추면 어떤 MCP 서버든 같은 방식==으로 붙는다. 도구마다 따로 통합 코드를 짤 필요가 없다. 그래서 브라우저·DB·이슈트래커를 같은 손동작(`/mcp`)으로 관리한다.

> [!WARNING] 외부 연결 = 권한·신뢰 점검
> MCP 서버는 ==외부 시스템에 접근==한다(DB 쓰기, 브라우저로 외부 사이트 접속 등). 신뢰할 수 있는 서버만 붙이고, 무엇을 할 수 있는지 확인한 뒤 쓴다. DB 쓰기·결제처럼 비가역 동작은 특히 권한 모드(§5)와 함께 본다.

## 5. 권한 모드 & 설정 계층 — 안전선 긋기

에이전트가 무엇을 ==자동으로 해도 되는지==는 권한 모드로 정한다. 너무 빡빡하면 매번 승인하느라 느리고, 너무 느슨하면 위험한 동작이 무방비로 실행된다. 작업 성격에 맞춰 고른다.

| 모드(대표 구분) | 동작 | 언제 |
|------|------|------|
| **읽기 전용 / 플랜** | 편집·실행 안 함, 탐색·계획만 | 큰 작업 전 계획 검토(세션 1 플랜 모드) |
| **승인 필요(기본)** | 편집·셸 실행 시 ==그때그때 승인== | 평상시 기본값 — 안전과 속도의 균형 |
| **자동 승인** | 승인 없이 진행 | ==신뢰된 격리 환경==·반복 작업에서 속도 우선 |

설정은 ==계층==으로 쌓인다 — 좁은 범위가 넓은 범위를 덮어쓴다.

```text
전역(~/.claude/)        모든 프로젝트 공통 기본값
   ▼ 덮어씀
프로젝트(.claude/, git 커밋)   팀 공유 설정·권한
   ▼ 덮어씀
로컬(개인·커밋 안 함)        내 머신에서만, 민감 설정
```

> [!IMPORTANT] 자동 승인은 "격리"와 한 쌍
> 자동 승인은 빠르지만, ==되돌리기 어려운 동작==(파일 삭제·푸시·외부 전송)까지 무방비로 실행될 수 있다. 신뢰된 격리 환경에서, 무엇을 허용할지 ==좁게 명시==해 쓴다. 글로벌 규칙에 적은 "비가역 작업은 확인 먼저"가 여기 그대로 적용된다.

> [!TIP] 권한 충돌은 계층으로 푼다
> "이 명령은 허용/차단"이 꼬이면, 어느 계층에서 정의됐는지부터 본다. 민감한 허용은 ==로컬(커밋 안 됨)==에, 팀 공통 규칙은 프로젝트에 둔다. `/permissions`로 현재 상태를 확인한다.

## 6. 과설정 경계 — 꼭 필요한 것만

규칙·훅·MCP는 강력하지만, ==과하게 깔면 느려지고 혼동==한다. 긴 `CLAUDE.md`는 컨텍스트를 먹고, 무거운 훅은 매 이벤트를 잡고, 안 쓰는 MCP 서버는 도구 목록만 어지럽힌다.

```text
[과설정 신호]
- CLAUDE.md가 한 화면을 넘김 → 핵심이 묻힘
- 훅 때문에 매 편집이 눈에 띄게 느려짐
- /mcp 목록에 안 쓰는 서버가 쌓임
- 권한 규칙이 너무 많아 뭐가 허용인지 모름

[처방]
- 자주 어기는 규칙만 남기고 정리
- 무거운 훅은 빈번한 이벤트에서 떼기
- 안 쓰는 MCP·커맨드 제거
- 권한은 좁고 명확하게
```

> [!NOTE] 세션 2 "치트시트" 원칙과 같다
> 명령을 다 외우지 않고 자주 쓸 5개만 골랐듯, 커스터마이징도 ==실제로 효과 본 것만 남긴다==. "있으면 좋을 것 같아서" 깔린 설정이 가장 먼저 정리 대상이다.

### A. 스택별 `CLAUDE.md` 규칙

같은 "핵심만"이라도 스택마다 자주 어기는 관례가 다르다. 내 프로젝트에서 ==실제로 반복해 말하게 되는 것==만 추린다.

JS/TS 프로젝트용 — 비동기·타입·포맷 관례를 못 박는다.

```markdown
# 프로젝트 규칙 (JS/TS)

## 코딩 스타일
- async/await만 사용 — `.then()` 체인 금지
- 타입은 `interface`로, 외부 경계엔 `unknown` 후 좁히기
- 포맷은 prettier 기본값 (수동 정렬 금지)

## 에러 처리
- 빈 catch 금지 — 최소 `console.error`, 가능하면 사용자 알림
- API 응답은 `{ data, error }` 형태로 통일

## 금지사항
- `any` 남발 금지 · 환경변수는 `.env`로 (하드코딩 금지)
```

Python 프로젝트용 — 의존성·타입힌트·예외 관례를 못 박는다.

```markdown
# 프로젝트 규칙 (Python)

## 코딩 스타일
- 타입 힌트 필수 (공개 함수 시그니처)
- 포맷·린트는 ruff 기준 (line-length 100)
- 의존성은 `pyproject.toml`로 관리 (pip 직접 설치 금지)

## 에러 처리
- 광범위한 `except Exception:` 금지 — 구체 예외만 잡기
- 삼키지 말 것 — 로깅 후 재발생 또는 명시적 처리

## 금지사항
- 가변 기본 인자(`def f(x=[])`) 금지 · print 디버깅 잔재 금지
```

### B. 훅(hooks) — 이벤트에 자동 실행

==자동으로 일어나야 하는 동작은 규칙이 아니라 훅==이다(§3). 아래는 "이벤트 → 명령" 짝을 보여주는 대표 형태로, 정확한 이벤트 이름·매처 문법은 `/hooks`로 확인한다.

예제 1 — 파일 편집/저장 후 포맷터 자동 실행 (`settings.json`).

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "prettier --write \"$FILE\"" }
        ]
      }
    ]
  }
}
```

예제 2 — 응답 완료 시 데스크톱 알림. 길게 도는 작업을 다른 창에서 기다릴 때 유용하다.

```text
이벤트: Stop (응답 완료)
  → 명령: 알림음 재생 / 데스크톱 토스트 띄우기
        (OS별로 다름 — macOS: afplay, Windows: SystemSounds 등)
```

> [!IMPORTANT] 이 둘의 공통점 — "내가 잊어도 돈다"
> 포맷이든 알림이든, `CLAUDE.md`에 "해줘"라고 적으면 건너뛸 수 있다. 훅은 ==이벤트가 나면 무조건== 실행된다. **자동 동작은 메모리가 아니라 훅**이라는 게 핵심이다.

### C. MCP — 외부 도구·데이터 붙이기

규칙·훅으로는 외부 시스템에 닿을 수 없다. 브라우저·DB 같은 외부 도구는 ==MCP 서버==로 표준 프로토콜로 붙인다.

예제 — 외부 도구 연결의 큰 그림과 `/mcp` 관리.

```text
1) MCP 설정에 서버 등록
   - 브라우저 자동화 서버  → 실제 페이지 열어 클릭·스크린샷
   - DB 서버              → 스키마 조회·쿼리 실행
   (서버마다 실행 방식·인증이 다르니 각 서버 문서를 따른다)

2) /mcp 로 관리
   - 연결된 서버 목록·상태 확인, 인증
   - 안 쓰는 서버는 여기서 정리
```

> [!WARNING] 셋 다 — 깔기 전에 "정말 필요한가"
> 규칙은 짧게, 훅은 가볍고 안전한 것만, MCP는 신뢰되고 실제로 쓰는 서버만. ==긴 `CLAUDE.md`·무거운 훅·안 쓰는 MCP 서버==는 전부 느려지고 혼동만 키운다(§6). "있으면 좋을 것 같아서"가 가장 먼저 정리 대상이다.

## ✅ 한 문장 요약

> [!TIP] 한 문장 요약
> ==커스터마이징은 도구를 내 프로젝트에 길들이는 3층이다 — 규칙(`CLAUDE.md`, 항상 주입)·훅(이벤트에 강제 실행)·MCP(외부 도구 연결).== 항상 일어나야 하는 동작은 규칙이 아니라 훅으로, 외부 연결은 MCP로, 그 위에 권한 모드·설정 계층으로 안전선을 긋되, 꼭 필요한 만큼만 깐다.

## 확인 문제

**Q1.** "커밋 전에는 반드시 테스트가 통과해야 한다"를 ==매번 강제==하고 싶다. `CLAUDE.md`에 규칙으로 적는 것과 훅으로 거는 것 중 무엇이 맞나?

> **정답:** 훅(`settings.json`).
> **해설:** `CLAUDE.md` 규칙은 매 대화 주입되지만 =='권유'==라 에이전트가 건너뛸 수 있다. 반드시 매번 실행돼야 하는 동작은 이벤트에 묶어 강제 실행하는 훅이 맞다(§3). 규칙은 맥락, 훅은 실행 보장.

**Q2.** 에이전트가 실제 브라우저로 페이지를 열어 동작을 확인하거나 사내 DB를 조회하게 하고 싶다. 어떤 커스터마이징 층인가?

> **정답:** MCP 서버 연결(`/mcp`로 관리).
> **해설:** 외부 도구·데이터 소스를 표준 프로토콜로 붙이는 게 MCP다(§4, 입문 레슨 05의 "도구계의 USB"). 규칙·훅으로는 외부 시스템에 접근할 수 없다.

**Q3.** 신뢰된 격리 환경에서 반복 작업 속도를 높이려 ==자동 승인==을 켰다. 함께 챙겨야 할 것은?

> **정답:** 허용 범위를 ==좁게 명시==하고, 비가역 동작(삭제·푸시·외부 전송)을 경계한다.
> **해설:** 자동 승인은 빠르지만 되돌리기 어려운 동작까지 무방비로 실행될 수 있다(§5). 격리 환경에서, 무엇을 허용할지 좁게 두고 설정 계층(로컬)으로 민감 권한을 관리한다.
